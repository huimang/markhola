# v0.7.8 字体大小测试文档

## 目标

验证 `v0.7.8` 增加 `View > Size` 子菜单，其中包含 `Zoom In`、`Zoom Out` 和 `Reset`，并将 `v0.7.7` 的现有文档字体大小保留为 `100%` 默认值。

同时验证用户选择的字号会被保存，关闭并重新打开应用后仍然生效。

## 自动化检查

1. 没有保存配置时，文档字号初始值为 `100`
2. 放大一次将 `100` 变为 `110`
3. 缩小一次将 `100` 变为 `90`
4. 放大上限为 `200`
5. 缩小下限为 `50`
6. 任意支持范围内的值执行重置后变为 `100`
7. 缺少保存配置时读取为 `100`
8. 无效或超出范围的配置读取为 `100`
9. `50..=200` 范围内符合 10% 步进的有效配置可以恢复
10. 放大后保存增加后的值
11. 缩小后保存减少后的值
12. 重置后保存 `100`
13. 初始应用外壳接收恢复后的字号
14. 应用外壳 HTML 暴露字号应用函数
15. 原生 `View` 菜单正确连接三个 `Size` 操作
16. 原生底部状态栏不包含字号或其他可操作控件
17. 字号只通过 `View > Size` 菜单调整

## 手动检查

### 默认外观

1. 启动应用并打开 `examples/view-size.md`
   预期：预览字体与 `v0.7.7` 现有外观一致

2. 切换到可写模式
   预期：编辑器文字和行号与 `v0.7.7` 现有外观一致

### 只读预览

1. 执行 `View > Size > Zoom In`
   预期：正文、标题、行内代码和代码块文字变大；底栏显示 `110%`

2. 再次执行 `Zoom In`
   预期：预览字体变为 `120%`

3. 执行 `Zoom Out`
   预期：预览字体恢复为 `110%`

4. 执行 `Reset`
   预期：预览字体恢复为原始 `100%`

5. 重复放大并超过 `200%`
   预期：显示字号停止在 `200%`

6. 重复缩小并低于 `50%`
   预期：显示字号停止在 `50%`

### 可写编辑器

1. 将字号设置为 `120%`，然后切换到可写模式
   预期：编辑器文字和行号都使用 `120%`

2. 输入、选择、滚动、缩进和取消缩进文字
   预期：编辑功能正常，行号保持垂直对齐

3. 执行 `Zoom Out`
   预期：编辑器文字和行号一起缩小，不丢失内容或选择范围

4. 执行 `Reset`
   预期：编辑器排版恢复为 `100%`

### 状态切换

1. 设置非默认字号，在只读和可写模式之间切换
   预期：字号保持不变

2. 打开多个 Markdown 文件并切换 Tab
   预期：所有 Tab 使用同一个字号

3. 在 Default、Dark 和 Light 主题之间切换
   预期：字号百分比保持不变，各主题仍保留自身正常排版比例

4. 进入并退出全屏
   预期：字号保持不变

5. 在同一次运行中触发应用外壳恢复
   预期：当前字号被重新应用

6. 将字号设置为 `130%`，退出并重新启动应用
   预期：展示文档内容前恢复为 `130%`

7. 执行 `Reset`，退出并重新启动应用
   预期：字号恢复为 `100%`

8. 删除已保存的字号配置并重新启动应用
   预期：字号使用默认 `100%`

### 应用外壳保持不变

1. 调整字号前后对比 Tab、预览标题栏、查找控件、对话框和原生底栏
   预期：这些元素的大小不发生变化；原生底栏不展示字号

## 验证命令

1. 运行 `cargo test`
2. 运行 `scripts/build_app.sh`
3. 启动 `dist/MarkHola.app`
4. 使用 `examples/view-size.md` 完成手动检查
5. 实现验证通过后，以 `UDZO` 格式生成发布 DMG
