# v0.8.0 macOS 原生窗口 Tab 技术设计

## 目标

`v0.8.0` 只替换文档 Tab 的展示与选择机制：

- 删除 WebView 内自绘的文档 Tab 条。
- 使用 macOS 原生窗口 Tab 展示已打开文档。
- 支持 `Command + 1` 到 `Command + 9` 按可见顺序切换文档。
- 保持现有打开、保存、关闭、未保存状态、主题、字号、Outline 和 Footer 行为。

本版本不把 MarkHola 改造成多个独立文档 Runtime。所有 `ActiveDocument` 继续由同一个 `DocumentWorkspace` 管理。

## 范围变化

旧方案要求每个文档拥有完整独立的 Window、WebView、Footer 和 Runtime，并支持 Tab 拆分与窗口重新合并。该方案已经作废。

新方案保留：

- 一个中央 `AppRuntime`
- 一个中央 `DocumentWorkspace`
- 一份应用级主题、语言、字号和资源访问状态
- 现有文档 ID、路径去重、保存与关闭逻辑

原生窗口对象只作为文档的轻量展示 Surface，不拥有独立的文档模型或业务 Runtime。

## 已确认范围

### 原生 Tab

- 每个已打开文档对应一个 macOS 原生窗口 Tab。
- 所有文档 Tab 保持在 MarkHola 管理的同一原生 Tab 组中。
- Tab 标题来自现有 `DocumentTabSnapshot`。
- dirty 文档继续显示未保存标记。
- 点击原生 Tab 时激活中央 `DocumentWorkspace` 中对应文档。
- `Command + 1` 到 `Command + 9` 激活当前原生 Tab 组中对应可见序号。
- 序号不存在时不改变当前文档。
- 保留现有前一个、后一个、关闭当前、关闭其他和关闭全部操作。

### 现有工作区行为

- `DocumentWorkspace` 继续集中保存全部 `ActiveDocument`。
- 同一路径再次打开时激活已有 Tab，不创建重复文档。
- 新建空白文档继续使用全局递增的 `Untitled-N` 标题。
- Save、Save As、打印、导出和模式切换继续作用于活动文档。
- Theme、界面语言和字号继续是应用级设置。
- Outline 和 Footer 继续反映当前活动文档。
- Footer 高度为 34 px，只显示 path、Words、Lines 和 mode，不再保留最右侧状态列。
- Footer 左右两侧文字统一使用同一种较低亮度的 Gray 前景色。
- 打开多个文件、Finder 打开、本地 Markdown 链接和拖放仍进入同一工作区。

### 空白工作区

- 启动时保留当前空白工作区。
- 第一个文档打开前不显示原生 Tab 条。
- 打开第一个文档时，当前主窗口成为第一个原生文档 Tab。
- 关闭全部文档后回到当前空白工作区，不创建新的业务 Runtime。

## 明确不在 v0.8.0 范围

- 每个文档独立的 `AppRuntime` 或 `DocumentWindowRuntime`。
- 每个文档独立持有自己的业务状态、偏好或资源注册表。
- 支持把 Tab 拆分为可独立工作的多文档窗口。
- 支持重新合并独立窗口。
- 跨多个独立窗口同步 Theme、字号、Outline 或 Footer。
- 恢复上次退出时的 Tab 分组。
- 自定义原生 Tab 的形状和动画。
- `v0.8.1` 的 Typora 风格行内编辑。
- Windows 或 Apple Intel 支持。

如 macOS 自身显示不属于 MarkHola 范围的窗口 Tab 菜单项，本版本不把它们作为受支持功能；MarkHola 只验证单个受管 Tab 组。

## 原生 Tab 配色

原生 Tab 的控件、布局、选中状态和交互继续由 AppKit 绘制，不重新实现 Tab 外形。MarkHola 只同步原生窗口外观和标题栏背景，使原生 Tab 与现有主题保持一致：

- Default 原生 Tab 和标题栏使用 Violet Tint `#F2F0FF`。
- Default 正文使用更浅的 Green Subtle `#FAFEFD`，与 Tab 形成同色系层级差异。
- Footer 独立使用 Gray 色系，不再跟随正文的绿色背景。
- Light 使用 Violet Tint `#F2F0FF`。
- Dark 使用现有深色主题背景 `#24213A`。
- Default 和 Light 使用系统 Aqua 外观，Dark 使用 Dark Aqua 外观。
- 主题变化同时广播到活动和非活动 Surface，避免切换 Tab 后恢复旧配色。

此策略保留 macOS 原生的文字、分隔线、悬停和可访问性行为，同时与 v0.7.8 已建立的紫色、绿色主题色系保持视觉连续。

v0.8.0 在原有 Tint 之上增加更浅的背景色阶：

- Violet Subtle `#F9F8FF`：Violet Tint 与白色按 50% 混合。
- Green Subtle `#FAFEFD`：用于接近白色的大面积正文背景。
- Gray Strong `#1E293B`、Gray `#475569`、Gray Mid `#94A3B8`、Gray Tint `#E2E8F0`、Gray Subtle `#F8FAFC`：组成第三套主色系，供 Footer 等中性界面使用。

Green Subtle 用于正文大面积基础背景，Violet Tint 用于原生 Tab 和标题栏，Green Tint 继续用于表头、悬停和强调状态；Gray 色系负责 Footer 等中性界面，以保留清晰的视觉层级。

## 技术约束

macOS 的 `NSWindowTabGroup` 由多个 `NSWindow` 组成。为了使用真正的系统窗口 Tab，同时避免独立文档 Runtime，本版本采用：

```text
AppRuntime
├── DocumentWorkspace
│   ├── ActiveDocument 1
│   ├── ActiveDocument 2
│   └── ActiveDocument N
├── SurfaceRegistry
│   ├── WindowId -> DocumentSurface
│   └── document_id -> WindowId
├── shared preferences
├── shared AssetAccessRegistry
└── active WindowId / document_id

DocumentSurface
├── Tao Window / NSWindow
├── WKWebView
├── NativeFooter
├── ShellRuntime
└── assigned document_id
```

`DocumentSurface` 只是 UI 容器。文档内容、路径、dirty 状态和模式仍只存在于中央 `DocumentWorkspace`。

## 激活模型

当用户切换原生 Tab：

1. 原生窗口获得 key/main 状态。
2. `WindowId` 通过 `SurfaceRegistry` 解析为 `document_id`。
3. 中央 `DocumentWorkspace::activate_document(document_id)` 更新活动文档。
4. 同步该 Surface 的 WebView、Footer、窗口标题和菜单状态。
5. 不复制或移动 `ActiveDocument`。

WebView IPC 和窗口事件携带来源 `WindowId`。编辑事件在更新中央 Workspace 前先激活来源文档，避免后台 Surface 修改错误文档。

## Surface 同步策略

每个文档 Surface 保留自己的 WebView DOM，但数据来源始终是中央 Workspace。

- 新建或打开文档后创建 Surface，并首次渲染该文档。
- 编辑事件更新 Workspace 中对应文档，并重新同步该 Surface 的标题、Footer 和 dirty 标记。
- Theme、语言和字号变化广播到全部 Surface。
- 文档保存后更新对应 Surface。
- 非活动 Surface 不因为另一个文档变化而重新渲染正文。
- 激活 Surface 时执行一次状态校准，确保菜单和 Footer 与中央 Workspace 一致。

## 打开与去重

1. 沿用 `DocumentWorkspace::find_by_path` 检查重复路径。
2. 已存在时取得 `document_id`。
3. 通过 `SurfaceRegistry` 找到对应原生窗口并激活。
4. 新文档先加入 Workspace，再创建 Surface 并加入受管 Tab 组。
5. Surface 创建失败时，从 Workspace 回滚刚加入的新文档。

多文件打开允许部分成功；成功文档按打开顺序加入原生 Tab 组。

## 关闭行为

### 关闭当前

1. 根据 key window 找到 `document_id`。
2. 沿用现有未保存确认。
3. 确认后从 Workspace 关闭文档。
4. 从 Surface Registry 删除对应 Surface。
5. 激活系统选中的相邻 Tab，并同步 Workspace 活动文档。

### 关闭其他与关闭全部

- 沿用中央 Workspace 的关闭确认顺序。
- 关闭成功的文档同时删除对应 Surface。
- 任一确认取消时停止后续关闭。
- 全部文档关闭后保留一个空白主窗口并显示现有 empty workspace。

### 应用退出

继续使用现有“检查中央 Workspace 中全部未保存文档”的退出流程，不引入多 Runtime 退出协调。

## 原生 Tab 适配层

新增 `native_tabs.rs`，集中封装 macOS API：

- 设置统一 `tabbingIdentifier`
- 把新 Surface Window 加入主 Tab 组
- 读取 Tab 组可见顺序
- 激活指定序号
- 激活指定 `NSWindow`
- 取得当前 key/main window
- 同步 Tab 标题和 dirty 表示

业务模块不直接散落 `objc2::msg_send!`。

## WebView 调整

删除以下 WebView 内容：

- `tabsShell`
- `tabsBar`
- `tabNavigation`
- `previousTabs`
- `nextTabs`
- `newDocumentTab`
- `renderTabs`
- Tab 点击、关闭和键盘事件
- Tab 条专用 CSS

保留：

- empty workspace
- readonly preview
- writable editor
- Outline
- Find / Replace
- Mermaid、MathJax、代码高亮和主题

`WorkspacePresentation` 可以暂时保留 `tabs` 数据以降低迁移风险，但 WebView 不再消费该字段。完成验证后再决定是否删除该字段；本版本不为此扩大文档模型重构。

## 新建文档入口

旧 WebView Tab 条中的 `+` 按钮随自绘 Tab 条删除。

本版本保留以下新建入口：

- `File > New`
- `Command + N`

不额外自绘一个新的 `+` 按钮，避免在原生 Tab 条旁再次引入自定义 Tab UI。

## 菜单与快捷键

- `Command + 1` 到 `Command + 9` 由原生菜单项发送选择序号事件。
- `Command + Shift + [` 和 `Command + Shift + ]` 继续切换前后文档。
- `Command + W` 继续关闭当前文档。
- Tab 菜单继续保留关闭其他和关闭全部。
- 菜单 enable/check 状态继续从中央 Workspace 的活动文档生成。
- 不把窗口拆分、移动和合并菜单加入 MarkHola 的受支持菜单。

## Rust Blueprint

### 当前痛点

1. `AppRuntime` 只持有一个 Window/WebView/Footer。
2. WebView Tab 点击直接发送文档 ID，没有原生 Window 映射。
3. `bootstrap.rs` 同时承担窗口、WebView、协议和拖放构建，超过 270 行。
4. `user_events.rs` 默认所有 IPC 都来自唯一 WebView，超过 330 行。
5. `native_footer.rs` 已超过 300 行，不应继续加入 Tab 布局逻辑。

### 目标文件结构

- `src/implementation/app/runtime.rs`
  - 保留中央 `AppRuntime`
  - 增加 `SurfaceRegistry`
  - 目标约 130–180 行
- `src/implementation/app/document_surface.rs`
  - 持有 Window、WebView、Footer、ShellRuntime 和 document ID
  - 目标约 160–200 行
- `src/implementation/app/surface_registry.rs`
  - 维护 WindowId/document ID 映射与活动 Surface
  - 目标约 140–180 行
- `src/implementation/app/native_tabs.rs`
  - 封装 `NSWindowTabGroup` 和序号切换
  - 目标约 150–200 行
- `src/implementation/app/webview_builder.rs`
  - 从 bootstrap 抽出可重复使用的 WebView 构建
  - 目标约 180–220 行
- `src/implementation/app/bootstrap.rs`
  - 只保留 EventLoop、中央 Runtime 和首个空白 Surface 装配
  - 目标约 100–140 行
- `src/implementation/app/surface_actions.rs`
  - 创建、激活、同步和销毁 Surface
  - 目标约 160–200 行

### 增量实现顺序

1. 提取可重复创建的 WebView/Surface 构建，不改变单窗口行为。
2. 引入 `SurfaceRegistry`，首个 Surface 仍按现有方式运行。
3. 打开第二个文档时创建轻量 Surface，并加入原生 Tab 组。
4. 将原生 Window 激活映射到中央 Workspace 文档激活。
5. 接入数字快捷键和现有关闭动作。
6. 广播 Theme、语言和字号到所有 Surface。
7. 删除 WebView 自绘 Tab UI。
8. 完成空白工作区和多文件入口回归。

每完成一个逻辑阶段都先保持测试通过，不一次性替换全部运行时。

## 所有权约束

- `AppRuntime` 独占 `DocumentWorkspace` 和 `SurfaceRegistry`。
- `DocumentSurface` 独占 Window、WebView、Footer 和 Shell 状态。
- `ActiveDocument` 始终只归中央 Workspace 所有，不进入 Surface。
- `document_id` 和 `WindowId` 用于映射，不克隆文档或窗口对象。
- Surface 回调只发送标识和动作，不直接持有 Workspace 引用。
- 创建或删除 Surface 时先结束对 Workspace 的短期借用，再修改 Registry。

## 失败处理

- Surface 创建失败时回滚对应新文档，不影响已打开文档。
- 原生 Tab 分组失败时关闭失败 Surface并报告错误，不保留受支持范围外的独立窗口。
- 找不到来源 Surface 的迟到事件直接忽略并记录日志。
- 多文件打开时汇总失败数量。
- 删除 Surface 前先完成未保存确认。
