# v0.8.0 macOS 原生窗口 Tab 测试方案

## 验证目标

验证 MarkHola 使用 macOS 原生窗口 Tab 替换 WebView 自绘 Tab，同时继续由一个中央 `DocumentWorkspace` 管理全部文档。

本方案不验证 Tab 拆分成独立工作窗口，也不验证多个独立文档 Runtime。

## 自动化测试

### Surface Registry

1. Window ID 和文档 ID 可以双向解析。
2. 注册 Surface 不会移动或复制中央 Workspace 中的文档。
3. 删除 Surface 后两侧映射同时移除。
4. 更新 active Surface 时可以得到正确文档 ID。
5. 已关闭 Surface 的迟到事件被安全忽略。

### 文档激活

1. 原生 Tab 获得焦点时激活对应 Workspace 文档。
2. 点击已打开路径时激活已有 Surface，不创建重复文档。
3. 前一个、后一个文档与原生 Tab 可见状态一致。
4. `Command + 1` 到 `Command + 9` 激活对应可见序号。
5. 不存在的序号不改变活动文档。

### 文档生命周期

1. 第一个文档复用启动主 Surface。
2. 后续文档创建新 Surface，并加入同一受管 Tab 组。
3. Surface 创建失败时回滚刚加入 Workspace 的文档。
4. 关闭当前文档同时删除对应 Surface。
5. 关闭其他和关闭全部继续使用中央 Workspace 的确认顺序。
6. 关闭全部后恢复空白工作区。
7. `Untitled-N` 继续在中央 Workspace 中递增。

### 来源路由

1. 每个 WebView 编辑事件更新其 Surface 对应文档。
2. Save、Save As、打印、导出和模式切换作用于当前原生 Tab。
3. 拖放和本地 Markdown 链接加入同一中央 Workspace。
4. Finder 打开已存在路径时激活已有原生 Tab。

### 状态同步

1. dirty 状态更新对应原生 Tab 标题。
2. Footer 显示当前原生 Tab 的路径、Words、Lines 和 mode。
3. Outline 切换作用于当前 Surface。
4. Theme、语言和字号应用到全部已创建 Surface。
5. 新 Surface 继承当前 Theme、语言和字号。

### Shell 回归

1. Shell HTML 不再包含自绘 Tab 条。
2. Shell JavaScript 不再生成、选择或关闭文档 Tab。
3. Workspace Chrome CSS 不再包含 Tab 条布局。
4. readonly、writable、Outline 和 Find 仍可正常渲染。
5. 空白工作区仍显示 MarkHola 图标和提示。
6. `WorkspacePresentation` 的兼容字段不会重新渲染 WebView Tab。

## 构建验证

```bash
cargo test
./scripts/build_app.sh
```

真机验证直接打开示例，避免使用原生文件选择器：

```bash
./scripts/qa_open_app.sh examples/native-tabs.md
```

验证前确认实际进程路径属于：

```text
<repo>/dist/MarkHola.app/Contents/MacOS/MarkHola
```

## 真机验证

### 状态一：单文档

1. 使用 `qa_open_app.sh` 打开 `examples/native-tabs.md`。
2. 确认正文上方没有旧 WebView Tab 条。
3. 确认第一个文档在 macOS 原生 Tab 中展示。
4. 确认窗口标题、Footer、Outline 和正文对应该文档。
5. 截图检查原生 Tab、WebView 和 Footer 的垂直布局。
6. 确认 Footer 高度为 34 px，文字仍保持垂直居中且不被裁切。
7. 确认 Footer 只显示 path、Words、Lines 和 mode；path 左对齐，Words、Lines 和 mode 在右侧各自右对齐，不存在最右侧状态列。
8. 确认 Footer 左右两侧文字使用同一种较低亮度的 Gray 前景色。

### 状态二：多个原生 Tab

1. 点击示例中的 `multi-document.md` 链接。
2. 确认第二个文档加入同一原生 Tab 组。
3. 再次点击该链接，确认不创建重复 Tab。
4. 使用 `Command + 1` 和 `Command + 2` 切换。
5. 使用前一个和后一个 Tab 菜单切换。
6. 确认正文、窗口标题和 Footer 随 Tab 一起变化。
7. 截图确认没有原生 Tab 与 WebView Tab 重复展示。

### 状态三：编辑和保存

1. 在第一个 Tab 切换到 writable 并修改内容。
2. 切换到第二个 Tab，确认其内容没有变化。
3. 切回第一个 Tab，确认修改和 dirty 状态保留。
4. 保存第一个文档，确认 dirty 标记消失。
5. 对新建 `Untitled-N` 文档执行首次保存，确认 Tab 标题更新。

### 状态四：关闭

1. 在一个 Tab 制造未保存修改。
2. 使用 `Command + W` 关闭，分别检查 Cancel 和 Save。
3. 确认 Cancel 后 Tab 和内容仍存在。
4. 使用关闭其他，确认未保存确认顺序正确。
5. 使用关闭全部，确认完成后回到空白工作区。

### 状态五：主题、字号和 Outline

1. 打开至少两个文档 Tab。
2. 切换 Theme，确认两个 Surface 都更新。
3. 确认 Default 标题栏使用低对比度的 Gray Tint 毛玻璃材质，原生 Tab 使用 Green Tint `#EAF9F5`，正文使用 Green Subtle `#FAFEFD`。
4. 确认 Footer 使用 Gray 色系，与绿色正文和 Tab 区分。
5. 确认 Light 标题栏使用 Gray Tint 毛玻璃材质，选中 Tab 使用 Green Tint `#EAF9F5`。
6. 确认 Dark 使用现有深色主题背景，并保持原生 Tab 文字可读。
7. 调整字号，确认切换 Tab 后两边字号一致。
8. 切换界面语言，确认原生菜单和 WebView 内容同步。
9. 在每个 Tab 分别验证 Outline，确认 Footer 始终对应当前文档。

### 状态六：文件入口

1. 拖入两个 Markdown 文件，确认按顺序加入同一 Tab 组。
2. 再次拖入已打开文件，确认激活已有 Tab。
3. 使用 Open File 多选，确认成功文件均进入同一工作区。
4. 使用 Finder 打开文件，确认进入当前应用实例。

### 状态七：空白工作区

1. 无文档启动应用，确认不显示空原生 Tab 条。
2. 新建第一个文档，确认主窗口成为第一个文档 Tab。
3. 关闭全部文档，确认回到带 Logo 的空白工作区。
4. 确认旧 WebView Tab 条和 `+` 按钮都不存在。
5. 确认 `File > New` 和 `Command + N` 仍可新建文档。

## 验收标准

- 全部 `ActiveDocument` 仍由一个中央 Workspace 管理。
- 文档通过 macOS 原生窗口 Tab 展示和选择。
- `Command + 1` 到 `Command + 9` 与原生可见顺序一致。
- 不存在旧 WebView Tab 条、`+` 和溢出导航。
- 打开、去重、编辑、保存、关闭和空白工作区行为正确。
- Theme、语言、字号、Outline 和 Footer 没有回归。
- 不要求 Tab 拆分、窗口合并或多 Runtime 同步。
- 自动化测试通过。
- 精确构建 App 的单文档、多 Tab 和空白工作区截图验证通过。

## 本地实现验证记录

- 验证 App：`dist/MarkHola.app`
- 验证进程：`dist/MarkHola.app/Contents/MacOS/MarkHola`
- 验证示例：`examples/native-tabs.md`、`examples/multi-document.md`
- 自动化结果：82 passed，1 ignored
- 真机结果：
  - 单文档不显示旧 WebView Tab 条。
  - 第二个文档进入同一个 AppKit 原生 Tab 组。
  - `Command + 1` 和 `Command + 2` 可以切换对应文档。
  - 拖动交换原生 Tab 顺序后，数字快捷键按新可见顺序切换。
  - `Command + W` 关闭当前 Tab，关闭全部后返回带 Logo 的空白工作区。
  - Default、Light、Dark 三种主题的原生 Tab 和标题栏配色均与现有主题一致；Default 和 Light 标题栏使用 Gray Tint 毛玻璃材质，Tab 使用 Green Tint，正文使用更浅的 Green Subtle `#FAFEFD`，Footer 使用 Gray 色系。
  - 原生 Footer 从 38 px 继续缩减为 34 px，有文档和空白工作区均未出现文字裁切或错位。
  - Footer 最右侧状态列已移除，仅保留左对齐的 path，以及在右侧各自右对齐的 Words、Lines 和 mode。
  - Footer 左右两侧文字统一使用同一种较低亮度的 Gray 前景色。
