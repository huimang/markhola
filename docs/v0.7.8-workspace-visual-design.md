# v0.7.8 工作区主视觉技术设计

## 范围

本功能调整原生 macOS 菜单下方的应用工作区。

范围包括：

- 文档 Tab 栏
- 统一承载只读文档信息的原生底部状态栏
- Tab 溢出导航
- Tab 栏中的新建文档快捷按钮
- 右侧 Outline / TOC 面板
- 编辑器行号的显示范围
- WebView 工作区与现有原生底栏之间的视觉关系
- 未打开文档时的居中 Logo 空状态
- Mermaid 失败渲染的页面根级临时节点清理

`v0.7.8` 的字体大小功能单独定义在：

- `docs/v0.7.8-view-size-design.md`
- `docs/v0.7.8-view-size-test.md`

## 已确认的视觉方向

以已确认的 `tmp/newtheme.html` 技术评估原型作为视觉方向，但不直接把原型代码当作生产实现。

生产界面应保留以下特征：

- 扁平且首尾相接的 Tab
- 细且清晰的结构分隔线
- 安静、干净的文档画布
- 克制使用 MarkHola Logo 主色
- 仅在控件有实际用途时展示控件

Logo 的两组强调色为：

- 紫色
- 绿色

主题 CSS 可以使用这两种颜色的加深或减淡版本，表达悬停、焦点和选中状态。

## 原生底部状态栏

删除 WebView 内位于 Tab 栏下方的 `document-toolbar`，不再保留第二条顶部文档功能区。

现有原生 macOS 底部状态栏继续位于 WebView 外部，并只承载不可操作的文档信息。布局顺序固定为：

`[文件路径] [Words] [Lines] [Readonly / Writable] [状态内容]`

最左侧文件路径使用剩余可用宽度；路径过长时单行省略。未保存的新文档显示 `Unsaved draft`。

右侧各区域行为如下：

- `Words` 和 `Lines` 显示活动文档统计
- 模式区域只显示 `Readonly` 或 `Writable`，不显示 `Mode` 前缀，也不可点击
- 状态区域只显示当前文档操作状态，不显示 `Status` 前缀
- 底栏不展示字号和 Outline，也不包含任何按钮或其他可操作控件

没有打开文档时，底部状态栏保留自身背景，但隐藏所有文档信息。

## Tab 栏

没有打开任何文档时隐藏整个 Tab 区域；空状态卡片显示在剩余页面的水平和垂直中心。卡片使用横向布局，左侧展示不包含字标和 slogan 的 `assets/app-icon.png`，右侧展示现有提示标题和说明。图标保持自身宽高比，不裁切、不拉伸，并提供可读的替代文本。打开第一个文档后恢复 Tab 区域。

Tab 区域使用紧凑的 `36px` 高度，相比早期实现上下各减少约 `5px`。

### 结构

Tab 栏不显示单独的 MarkHola `brand-mark`。

每个文档 Tab 只包含：

- Markdown 文件名
- 文档存在未保存修改时的现有脏状态标记
- 关闭按钮

因为工作区只支持 Markdown 文档，所以 Tab 不显示文件类型图标。

### 活动 Tab

活动 Tab 使用来自 MarkHola Logo 色板的单色下划线。

下划线不使用双色渐变。生产主题统一使用绿色活动下划线，紫色用于相容的悬停、焦点或辅助强调状态。

活动 Tab 的表面与下方文档画布保持视觉连接。

### 非活动 Tab

非活动 Tab 使用中性表面。悬停和焦点状态可以使用由 Logo 紫色或绿色减淡得到的颜色。

在以下三个主题中，非活动 Tab 都必须保持清晰可读：

- `default`
- `dark`
- `light`

### 新建文档快捷按钮

`+` 按钮固定在 Tab 栏最右侧，作为新建空白 Markdown 文档的快捷入口。

`+` 不属于可横向滚动的 Tab 内容。无论打开多少文档或 Tab 当前滚动到什么位置，`+` 都必须始终可见。

点击 `+` 必须复用现有 `UserEvent::NewDocument` 流程，其行为与以下入口一致：

- `File > New`
- `Command + N`

新建文档完成后，该文档成为活动 Tab。

### 移除无用途控件

Tab 栏不显示通用的 `more-button`。当前 `v0.7.8` 没有需要该按钮承载的操作。

## Tab 溢出导航

### 显示条件

当所有 Tab 都能在可用宽度内完整显示时：

- 隐藏向前和向后移动按钮
- Tab 内容使用完整可用宽度

当 Tab 发生溢出时：

- 在 `+` 左侧显示向前和向后移动按钮
- `+` 始终固定为 Tab 栏最右侧控件
- 所有 Tab 保持在同一横向行内
- Tab 不换行

溢出状态的布局为：

`[可横向滚动的文档 Tabs] [‹] [›] [+]`

按钮含义：

- `‹` 向较早的 Tab 移动
- `›` 向较后的 Tab 移动

### 交互行为

每次点击导航按钮，应横向移动足够距离，使该方向上的更多 Tab 进入可见区域。

以下情况发生时，应用外壳重新计算 Tab 是否溢出：

- 窗口大小变化
- 打开文档
- 新建文档
- 关闭文档
- 重新渲染 Tab 列表

当某个 Tab 变为活动状态时，如果它当前不可见，应用外壳自动将其滚动到可见区域。

Tab 滚动仅属于展示状态，不得改变文档顺序、活动文档 ID、脏状态或工作区持久化数据。

## Outline / TOC 面板

### 开关

在 `View` 菜单中提供 `Outline` 菜单项。

选择后在工作区右侧打开 Outline 面板，并显示菜单勾选状态；再次选择后关闭面板并取消勾选。

面板内部也提供关闭按钮。无论从哪个入口关闭，都产生相同结果。

以下情况禁用 Outline 菜单项并取消勾选：

- 没有打开文档
- 当前处于可写模式

可写模式的标题导航不属于 `v0.7.8` 范围。

### 内容

Outline 面板根据活动只读文档渲染后的标题生成：

- `h1`
- `h2`
- `h3`
- `h4`
- `h5`
- `h6`

条目保持文档标题顺序，并通过缩进展示标题层级。

点击条目后，只读文档滚动到对应标题。

文档没有标题时，面板显示简短空状态，不显示空白列表。

Outline 是独立导航视图，不要求 Markdown 包含 `[toc]` 占位符。现有正文内 `[toc]` 渲染继续独立工作。

### 文档切换

活动文档发生变化时，Outline 内容更新为新文档的标题。

在多个只读文档之间切换时，面板可以保持打开。新文档没有标题时显示空状态。

切换到可写模式时，关闭 Outline 面板、取消勾选并禁用菜单项。

## 只读和可写布局

### 只读模式

只读模式不显示左侧 reading rail 或行号列。

文档画布使用 Outline 面板左侧的全部可用宽度。

### 可写模式

可写模式继续使用现有编辑器行号列。

行号必须：

- 与编辑器文字保持垂直对齐
- 跟随编辑器滚动
- 与编辑器文字一起响应独立的 `View > Size` 设置

本功能不增加第二套 rail，也不重新实现行号逻辑。

原生底栏不跟随文档字号缩放。三个主题继续保证 WebView 边界和底栏文字清晰可读。

## 实现方案

### 应用外壳结构

更新应用外壳 HTML，增加：

- 可横向滚动的 Tab 区域
- 固定在右侧的 `+` 新建文档按钮
- 按需显示的前后 Tab 导航按钮
- 右侧 Outline 面板

Tab 栏不增加 brand-mark、Markdown 图标或通用 more-button。无文档空状态单独复用现有 `assets/app-icon.png`，不把图标放入 Tab 栏或原生底栏。

应用外壳 HTML 删除 `document-toolbar`、路径、模式、字号和 Outline 顶部控件，只保留右侧 Outline 面板以及用于无障碍状态通知的非视觉状态节点。

新建空白文档使用独立于已打开文件数量的递增序号，Tab 与窗口标题依次显示 `Untitled-1`、`Untitled-2`。关闭较早的空白文档后不回收其序号，后续新建文档继续递增，避免与仍存在的草稿重名。保存后继续使用用户选择的真实文件名。

### 应用外壳行为

扩展应用外壳脚本：

- 渲染无文件图标的文档 Tab
- 从 `+` 发送新建文档操作
- 检测 Tab 是否溢出
- 显示或隐藏溢出导航
- 横向滚动 Tab 区域
- 保证活动 Tab 可见
- 根据渲染后的标题生成 Outline
- 打开、关闭和刷新 Outline 面板
- 在 Mermaid 渲染成功或失败后清理其页面根级临时节点，避免错误 SVG 绕过正文容器并占满窗口宽度
- 暴露供原生 View 菜单调用的 Outline 显隐函数

HTML 和 PDF 导出使用相同的清理规则，确保失败渲染不会在导出页面中留下页面根级错误节点。

### Rust 事件桥接

仅按需要扩展应用外壳 IPC，将 `+` 操作映射到现有 `UserEvent::NewDocument`。

不得增加第二套新建文档实现。

Tab 滚动位置和 Outline 开关状态属于 WebView 展示状态，不需要持久化。

### 主题 CSS

增量更新每个现有主题样式：

- 保留主题自身背景和文字特征
- 使用统一的扁平 Tab 几何结构
- 使用 Logo 衍生的活动和交互强调色
- 设置右侧 Outline 面板样式
- 保留编辑器行号行为

本功能不进行无关主题重构或 CSS 架构调整。

## 无障碍要求

- 每个 Tab 保持键盘可聚焦
- 关闭按钮保留对应文档的无障碍标签
- `+`、前进、后退、View 菜单中的 Outline 和面板关闭按钮具有明确名称
- 原生底栏只包含不可操作的文本信息
- 隐藏的溢出控件不进入键盘焦点顺序
- Outline 条目使用链接或按钮，并提供清晰焦点状态
- 颜色不是唯一的活动 Tab 信号；下划线和与画布相连的活动表面共同表达状态

## 不在本次范围

- 支持非 Markdown 文件
- 拖动调整 Tab 顺序
- 固定 Tab
- Tab 右键菜单
- 通用 Tab 更多菜单
- 持久化 Tab 滚动位置
- 编辑 TOC 或拖动标题
- 可写模式中的标题导航
- 将原生底栏移回 WebView
- 重新实现编辑器行号

## 验证策略

### 自动化验证

- 应用外壳包含新建文档和溢出导航控件
- 应用外壳不包含 `document-toolbar`
- 应用外壳不包含 brand-mark、文件类型图标或 more-button
- 无文档空状态包含使用现有内嵌 App 图标数据的图片和替代文本
- 连续新建空白文档时标题使用单调递增的 `Untitled-N`
- `+` 的 IPC 映射到 `UserEvent::NewDocument`
- 只读 Outline 按标题顺序和层级生成
- 无标题文档产生 Outline 空状态
- 三个主题 CSS 包含所需 Tab 和 Outline 选择器
- 原生底栏按顺序包含路径、Words、Lines、Readonly/Writable 和状态文本，且不包含按钮
- View 菜单包含可勾选的 Outline 项

### 手动验证

- 验证无文档状态的图标在左、文字在右，整体保持居中，图标不变形且在浅色、深色背景下可辨认
- 验证连续新建和关闭空白文档时 `Untitled-N` 序号继续递增
- 将构建后的应用与已确认视觉方向对比
- 验证正常和溢出两种 Tab 状态
- 验证 `+` 始终固定在最右侧并能新建文档
- 验证 Outline 打开、关闭、导航和文档切换
- 验证只读模式没有左侧 rail
- 验证可写模式行号保持对齐
- 验证三个主题与字体大小功能保持兼容
- 验证底栏从左到右的顺序、路径省略、纯文本模式值、纯文本状态值以及无可操作控件
- 验证 View 菜单中的 Outline 勾选状态与面板显隐一致
