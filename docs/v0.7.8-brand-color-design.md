# v0.7.8 品牌色系技术设计

## 目标

`v0.7.8` 在现有 `default`、`dark`、`light` 三套主题中定义统一的 MarkHola 品牌色，并让只读 Markdown 表格的表头使用淡绿色。

本次是现有主题样式的增量改进，不增加新主题、不调整主题切换方式，也不改变表格结构。

## 品牌色规范

三套主题的 `:root` 都定义以下 CSS 自定义属性，名称和值保持一致：

| 色彩名称 | CSS 自定义属性 | 色值 |
| --- | --- | --- |
| MarkHola Violet | `--markhola-violet` | `#6657E8` |
| Violet Mid | `--markhola-violet-mid` | `#ACA4F4` |
| Violet Tint | `--markhola-violet-tint` | `#F2F0FF` |
| MarkHola Green | `--markhola-green` | `#17B890` |
| Green Mid | `--markhola-green-mid` | `#81D9C3` |
| Green Tint | `--markhola-green-tint` | `#EAF9F5` |

`Violet Mid` 和 `Green Mid` 分别取对应主色与 Tint 的 RGB 中点并取整，作为两端之间稳定、可复现的中间过渡色。

这些属性是品牌基础色，不取代各主题现有的 `--bg`、`--text` 等中性语义色。现有通用强调色改为兼容别名：`--accent` 指向 `--markhola-violet`，`--accent-strong` 指向 `--markhola-green`，从而清除三套主题原有的不一致蓝色或青绿色强调色。

## 统一使用原则

品牌色只统一“强调、交互和选中”相关样式。页面背景、正文文字、分隔线等中性色继续由各主题决定；警告、错误、查找结果高亮继续保留 `--warn`、`--danger` 和黄色查找语义，避免颜色含义混淆。

当前 `workspace_chrome.css` 自己定义的 `--brand-violet`、`--brand-violet-soft`、`--brand-green` 和 `--brand-green-soft` 将被移除。工作区与 Markdown 正文都直接消费主题 CSS 中的六个 `--markhola-*` 属性，避免出现两套品牌色来源。

六个颜色按以下层级使用：

| 使用场景 | 颜色 |
| --- | --- |
| 紫色主强调、链接、键盘焦点、紫色悬停文字 | MarkHola Violet `#6657E8` |
| 紫色悬停或焦点边框 | Violet Mid `#ACA4F4` |
| 紫色悬停背景 | Violet Tint `#F2F0FF` |
| 绿色活动状态、活动 Tab 横线、模式指示、绿色强调文字 | MarkHola Green `#17B890` |
| 绿色活动状态边框 | Green Mid `#81D9C3` |
| 绿色活动状态背景、Markdown 表头 | Green Tint `#EAF9F5` |

### Tab

- 活动 Tab 底部横线使用 `--markhola-green`
- Tab 鼠标经过背景使用 `--markhola-violet-tint`
- Tab 鼠标经过的强调文字和键盘焦点框使用 `--markhola-violet`
- 新建 Tab 与 Tab 前后导航按钮使用相同的紫色悬停规则
- 活动 Tab 本体继续使用主题画布背景，不额外铺满品牌色

### Markdown 链接

- 链接文字使用 `--markhola-violet`
- 鼠标经过时保持可识别的下划线，并使用 `--markhola-green`
- 已访问状态不另设第三套颜色，避免脱离品牌色系

### Outline

- Outline 开关在鼠标经过或展开时使用 Green Tint 背景、Green Mid 边框和 MarkHola Green 文字
- Outline 条目与关闭按钮在鼠标经过或键盘聚焦时使用 Violet Tint 背景和 MarkHola Violet 文字
- Outline 标题、空状态及未交互条目继续使用主题中性色，保证层级安静

### 其他强调状态

现有以下强调色也统一到同一套品牌色：

- 字号按钮、Tab 导航按钮和新建按钮的悬停/焦点状态
- 模式指示点及其外围色
- 查找输入框焦点和普通查找按钮悬停状态
- Markdown 引用块左边线
- About 面板复制按钮的双色渐变与阴影

其中紫色用于通用交互与链接，绿色用于活动、确认或当前状态。删除、错误、警告及查找命中仍使用原有语义色。

## 代码展示色系

本节只针对只读 Markdown 中的 fenced code block。可写模式仍是 Markdown 源文本编辑器，本次不增加编辑器内语法高亮。

### 当前问题

当前代码块的外层、代码区和行号区使用固定灰色与白色透明层；语法高亮由 Rust 中 Syntect 的 `base16-ocean.dark` 固定主题生成内联色值。这些颜色不来自 App 主题 CSS，因此仅修改 CSS 无法统一关键字、字符串和常量颜色。

### 代码块表面

三套主题增加同名的代码语义属性，并由 MarkHola 品牌色派生：

| 使用场景 | 色系规则 |
| --- | --- |
| 代码区背景 | MarkHola Violet 与深色中性表面的混合色 |
| 行号区背景 | 比代码区稍亮的紫色派生表面 |
| 行号文字 | Violet Mid |
| 行号分隔线 | MarkHola Violet |
| 普通代码文字 | Violet Tint |
| 语言标签背景 | MarkHola Green |
| 语言标签文字 | Violet Tint |

代码区与行号区继续保持现有 Grid 结构、同步行高、滚动行为、圆角和内边距，只替换颜色来源。

### 语法高亮

Rust 不再加载 `base16-ocean.dark` 作为代码高亮主题，改为一个小型 MarkHola Syntect 主题。颜色映射为：

| 语法类别 | 颜色 |
| --- | --- |
| 关键字、控制语句、存储类型 | Violet Mid |
| 字符串、正则表达式 | Green Mid |
| 数字、常量、语言内建值 | Green Tint |
| 函数名、类型名、属性名 | Violet Tint |
| 注释 | Green Mid，并保留与代码正文可区分的字体样式 |
| 无法分类的普通文本 | Violet Tint |

语法色仍由 Syntect 根据语言 scope 生成，不通过字符串替换修改 HTML。输出继续使用现有代码行结构，因此行号对齐、语言识别和不支持语言的纯文本回退保持不变。

### Rust 实现边界

`src/implementation/markdown.rs` 当前同时负责 Markdown 事件处理、代码块 HTML、语言解析和 Syntect 资源。为了不继续把品牌主题构造逻辑堆进现有大文件，本次只新增一个较小的语法主题模块，由 `markdown.rs` 调用：

- `src/implementation/markdown/syntax_theme.rs`：约 80–120 行，构造 MarkHola Syntect `Theme`
- `src/implementation/markdown.rs`：只替换主题资源初始化和调用，不移动 Markdown 解析、语言解析或 HTML 结构

这不是对现有 Markdown 模块的全面重构；不拆分其他职责，不改变公开接口。

## 表头样式

`themes/default/layout.css`、`themes/dark/layout.css`、`themes/light/layout.css` 中现有的 `.markdown-body thead` 统一使用：

```css
background: var(--markhola-green-tint);
```

表头背景最终显示为精确的 `#EAF9F5`，不再使用各主题原有的透明强调色。

为了让淡绿色表头在三套主题中都保持可读：

- `default` 和 `light` 继续使用各自的深色正文文字
- `dark` 为表头指定适合浅色背景的深色文字
- 单元格边框、内边距、对齐和字体保持现状

## 影响范围

修改范围限定为：

- `PLAN.MD` 的 `v0.7.8` 工作区视觉条目
- 三套 `themes/<theme>/layout.css` 的品牌色定义、Markdown 强调色与表头样式
- `src/implementation/app/workspace_chrome.css` 的 Tab、工具栏和 Outline 强调色
- `src/implementation/markdown.rs` 与新增语法主题模块中的代码高亮主题
- 对应自动化测试
- `examples/brand-colors.md`
- `README.md` 的版本与用户可见能力说明

HTML 导出和 PDF 导出当前会加载默认主题 CSS，因此它们会自然获得同一品牌色定义和淡绿色表头，不新增导出专用样式分支。
