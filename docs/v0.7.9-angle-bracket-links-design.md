# v0.7.9 尖括号链接简写设计

## 背景

当前 MarkHola 依赖 `pulldown-cmark` 渲染标准 Markdown。标准语法已经支持：

- `[text](url)` 普通链接
- `<https://example.com>` 这类自动链接

但不支持用户这次要求的简写：

```markdown
<xx>
```

期望把它当成：

```markdown
[xx](xx)
```

这属于对现有 Markdown 链接能力的小增强。由于 `v0.7.9` 在 2026-07-26 仍未提交和打 tag，
本功能直接并入 `v0.7.9`。

## 目标

- 在只读渲染中支持 `<xx>` 语法。
- 渲染结果等价于 `[xx](xx)`。
- 不改变可编辑源码，writable mode 中仍显示用户原始输入 `<xx>`。
- 不影响标准 `[text](url)`、`<https://...>`、`<mailto:...>`、图片、代码块、行内代码和
  HTML 标签的既有行为。

## 非目标

- 不引入完整的自定义 Markdown 方言系统。
- 不支持在 `<...>` 内再写单独的显示文本，例如 `<text|url>`。
- 不把所有尖括号内容都强制变成链接。
- 不改写保存到磁盘的 Markdown 源文。

## 当前实现分析

当前 Markdown 渲染入口是 `src/implementation/markdown.rs` 的 `render_html(markdown)`。
它当前只做两类预处理：

- `[toc]` -> 内部占位符
- 后续交给 `pulldown-cmark` 解析

因此，这次最小改动位置仍然应该是“解析前预处理”。如果在 HTML 输出阶段再回头改链接：

- 很难避开代码块、行内代码和原生 HTML
- 更容易误伤已有 autolink 语义

## 方案

### 1. 在 Markdown 预处理阶段新增尖括号链接转换

在 `preprocess_toc(...)` 旁边新增一个顺序明确的预处理步骤，例如：

```text
preprocess_angle_bracket_links(markdown)
```

输入中形如：

```markdown
<xx>
```

输出为：

```markdown
[xx](xx)
```

然后再继续进入现有 `pulldown-cmark` 渲染流程。

### 2. 只转换“像路径或目标”的尖括号内容

为了避免把普通 HTML 标签误转成链接，本次只转换满足下列条件的尖括号内容：

- 不包含空白
- 不以字母开头后紧跟 `>` 形成常见 HTML 标签，如 `<b>`、`<div>`
- 不以 `/` 开头的闭合标签，如 `</div>`
- 不包含 `=`、引号等更像 HTML attribute 的字符
- 允许常见链接/路径字符，例如：
  - `README.md`
  - `docs/intro.md`
  - `./notes`
  - `../guide`
  - `file:///tmp/a.md`
  - `https://example.com`

本次判断以“尽量覆盖路径/URL，同时避开明显 HTML 标签”为准，不追求完整 URL 语法校验。

### 3. 跳过代码语义区域

预处理必须跳过以下区域：

- fenced code block
- indented code block
- inline code span

原因是这些区域中的 `<xx>` 应保持源码字面量，不应被解释为链接。

### 4. 保持与现有 autolink 的关系

对于已经是标准自动链接的内容，例如：

```markdown
<https://example.com>
```

即使预处理把它改成 `[https://example.com](https://example.com)`，最终渲染语义也仍然正确。
因此本版本允许这种等价替换，不额外区分“保持 autolink 原样”与“转成普通链接”。

## 示例方向

新增 `examples/angle-bracket-links.md`，用于验证：

- `<README.md>` 这类本地路径
- `<https://example.com>` 这类 URL
- 行内代码 `` `<README.md>` `` 不转换
- fenced code block 中的 `<README.md>` 不转换

## 测试方向

需要覆盖：

1. `<xx>` 渲染成链接
2. `<README.md>` / `<docs/intro.md>` / `<https://...>` 等典型样例
3. 行内代码不转换
4. fenced code block 不转换
5. 原生 HTML 片段不误转

## 风险

最大风险是把 HTML 标签误识别成链接，因此预处理规则必须偏保守。宁可少转一部分模糊场景，
也不要把 `<div>`、`<span>` 之类误改成链接。

另一个风险是预处理与代码块边界处理不严谨，导致代码示例被改写。这个需要通过源码级测试
直接锁住。
