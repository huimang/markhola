# v0.7.9 界面改进技术设计

## 背景

v0.7.9 包含四项相关的界面改进：

- 增加 English 和简体中文两种界面语言，默认 English。
- 让 WebView 文档 Tab 的文字像原生 Tab 一样不能被鼠标拖选。
- 修复 `View` 菜单中 Outline 行没有可见标题的问题，并移除当前无用的 AppKit
  窗口标签菜单。
- 将内置 Help 的版本和内容同步纳入每次发布的阻断检查。

本次多语言只覆盖 MarkHola 自己创建的用户界面，不翻译用户打开的 Markdown 内容，
也不接管 macOS 自己提供的文件选择器、打印面板等系统界面语言。

## 现状与原因

当前原生菜单、WebView 空状态、查找面板、Outline、About、状态消息和确认提示均为英文
硬编码。主题和文档字号已通过 `NSUserDefaults` 持久化，因此语言偏好可以沿用相同机制。

文档 Tab 是 WebView 中的 `.document-tab` 元素，未设置 `user-select`，所以拖动标题文字时
会产生网页文本选区；这与原生 Tab 的交互不一致。

Outline 通过共享 `action` helper 创建，但该 helper 只把固定标题转换为静态
`NSString`。`Outline` 未进入映射，最终得到空标题。

`Show Tab Bar` 和 `Show All Tabs` 则是 AppKit 注入的标准项目，对应
`toggleTabBar:` 和 `toggleTabOverview:`。它们没有接入当前 WebView 文档模型，会与
MarkHola 自己的 `Tab` 菜单产生概念冲突。

## 目标

- 首次启动或没有已保存偏好时使用 English。
- 提供 `View > Language > English / 简体中文`，当前语言显示勾选。
- 切换语言后立即更新 MarkHola 的原生菜单、WebView 静态界面、运行状态消息、确认提示
  和 Help，不要求重启；重启后保留选择。
- Tab 标题不能形成文本选区，同时保持点击激活、关闭、键盘焦点、溢出导航和无障碍属性。
- Outline 在两种语言下都有可见标题，并保持既有禁用、启用、勾选和面板切换逻辑。
- 当前 WebView Tab 架构下不显示两个 AppKit 窗口标签命令，保留 MarkHola 自己的
  `Tab` 菜单。
- 从 File 菜单移除重复的 `Toggle Mode`，只在 Edit 菜单保留该命令，同时继续支持
  `Command + /`。
- English 和简体中文 Help 都与 `v0.7.9` 功能保持一致。

## 多语言方案

新增轻量的 `AppLanguage` 类型：

```text
English      -> key "en", label "English"
SimplifiedChinese -> key "zh-CN", label "简体中文"
```

语言偏好使用新的 `appLanguage` key 存入 `NSUserDefaults`。没有值或值无效时返回
English，不根据系统语言自动切换，从而满足默认 English 的要求。运行时保存当前
`AppLanguage`。

在仓库根目录新增 `i18n/`，每种语言使用一个 YAML 文件：

```text
i18n/
├── en.yaml
└── zh-CN.yaml
```

两个文件使用完全相同的稳定文案 key。Rust 源码只保留语言枚举、YAML 加载、默认回退和
类型化访问逻辑，不直接保存 English 或简体中文界面文案。English 文件是缺失 key 的
回退来源；启动和自动化测试会验证两个文件能够解析且 key 集合一致。

YAML 文案覆盖范围为：

- MarkHola 创建的全部原生菜单标题。
- WebView 的 Tab 无障碍标签、空工作区、查找/替换、Outline 和 About 文案。
- 原生 footer 与 WebView 中显示的操作状态和错误消息。
- MarkHola 创建的未保存确认提示。

About 页脚在两种语言中统一强调“免费的 Markdown 阅读器，基于 AI 构建”，不将当前
macOS/Apple Silicon 实现描述为长期的平台限定。

文件名、路径、Markdown 正文、PDF/HTML 等技术格式名不翻译。macOS 文件选择器、打印
面板以及其他系统提供界面继续跟随系统语言。

原生菜单安装函数接收当前语言。选择另一种语言时保存偏好并重建主菜单，再恢复当前主题、
Outline 和语言勾选状态。菜单 action 和快捷键保持不变。WebView 新增
`window.applyAppLanguage(...)`，接收当前语言的序列化文案表，原位更新静态 DOM 属性和
文本；不重新加载页面，不触碰当前文档、编辑内容、光标、撤销栈或 Tab 顺序。

运行中产生的状态消息和确认提示通过同一文案目录按当前语言生成，避免只翻译静态外壳。
动态内容使用带参数的专用方法，不在 UI 层拼接英文句子。

## Help 方案

保留 `assets/help/Documentation.md` 作为 English Help，新增
`assets/help/Documentation.zh-CN.md` 作为简体中文 Help。`Help > Documentation`
根据当前语言打开对应文件；若中文文件意外缺失，则回退到 English 文件并显示当前语言的
错误状态。

构建脚本继续复制整个 `assets/help` 目录。发布回归脚本同时检查两个 Help 文件存在，
并验证两者的 `Current version` 都等于 `Cargo.toml` 版本。

## Tab 方案

在 `.document-tab` 上增加：

```css
user-select: none;
-webkit-user-select: none;
```

仅禁止文本选择，不阻止 Tab 自身的 pointer/click/keyboard 事件，不改变关闭按钮、
焦点样式和现有 ARIA tab 语义。拖拽重排不属于本版本。

## View 菜单方案

菜单构造器改为根据当前语言直接创建可见 `NSString`，不再依赖缺项后返回空字符串的
标题分支，因此 English 显示 `Outline`，简体中文显示 `大纲`。

在原生主菜单安装完成后，从 `View` 子菜单中移除 action 为
`toggleTabBar:` 和 `toggleTabOverview:` 的 AppKit 标准项目。使用 selector
识别项目，不依赖系统显示语言下的标题。

如果 AppKit 在主菜单设置完成后才注入标准项目，则清理动作必须发生在
`setMainMenu` 之后。最终以真实运行菜单为准，确保两个项目不会在首次打开 View 菜单时
重新出现。

## 非目标

- 不增加除 English 和简体中文之外的语言。
- 不根据系统区域自动选择语言。
- 不翻译 Markdown 内容、文件名、路径或导出文档内容。
- 不接管 macOS 系统界面的语言。
- 不引入第三方国际化框架或在线翻译资源。
- 不增加独立 Preferences 窗口。
- 不实现 Tab 拖拽重排或原生窗口 Tab。
- 不修改 Outline 面板宽度、颜色或标题层级。
- 不修改 Outline 条目生成和点击滚动逻辑。
- 不添加 Outline 快捷键。
- 不删除 MarkHola 自己的 `Tab` 菜单。
- 不删除 Edit 菜单中的 `Toggle Mode` 或改变 `Command + /` 快捷键。
- 不提前实现 `v0.8.0` 的原生窗口标签；届时可按正式设计重新启用需要的 AppKit
  标签能力。
- 不修改 `v0.8.0` 原生窗口标签或 `v0.8.1` 混编编辑规划。

## 风险

语言切换若通过重载整个 WebView 实现，会破坏未保存编辑状态，因此本设计要求原位更新
文案。原生菜单重建时必须恢复当前 enable/check 状态，并保持 target 生命周期稳定。

中文文案长度可能改变查找面板、About 和菜单布局，必须通过真实渲染验证。Tab 禁止选择
不能覆盖关闭按钮的点击与键盘焦点。菜单清理还需要注意 AppKit 的注入时机，避免清理过早
后项目在首次打开菜单时重新出现。

最终必须使用真实 AppKit 菜单、无障碍树和截图验证，不能只依赖源码字符串测试。
