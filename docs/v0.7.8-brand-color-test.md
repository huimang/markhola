# v0.7.8 品牌色系测试文档

## 测试目标

验证三套 App 主题都定义同一组 MarkHola 品牌色，Tab、链接、Outline、代码展示和其他强调状态统一消费该色系，并验证只读 Markdown 表格表头在真实渲染中使用 `#EAF9F5` 淡绿色且文字清晰可读。

## 自动化检查

1. `default`、`dark`、`light` 三套主题都包含：
   - `--markhola-violet: #6657E8`
   - `--markhola-violet-mid: #ACA4F4`
   - `--markhola-violet-tint: #F2F0FF`
   - `--markhola-green: #17B890`
   - `--markhola-green-mid: #81D9C3`
   - `--markhola-green-tint: #EAF9F5`
2. `Violet Mid` 和 `Green Mid` 的值分别等于对应主色与 Tint 的 RGB 中点取整结果
3. 三套主题的 `--accent` 和 `--accent-strong` 分别指向 MarkHola Violet 与 MarkHola Green
4. 三套主题的 `.markdown-body thead` 都引用 `var(--markhola-green-tint)`
5. Markdown 链接引用 `var(--markhola-violet)`，悬停状态引用 `var(--markhola-green)`
6. 工作区 CSS 不再定义第二套 `--brand-*` 颜色值
7. 活动 Tab 横线引用 `var(--markhola-green)`
8. Tab 悬停引用 Violet Tint，键盘焦点引用 MarkHola Violet
9. Outline 展开状态引用绿色三级色，条目悬停引用紫色三级色
10. 模式指示、字号按钮、查找焦点、引用边线和 About 按钮不再使用旧蓝色或旧青绿色硬编码强调色
11. 深色主题为浅色品牌背景提供清晰的深色文字
12. 三套主题的代码区、行号区、分隔线和语言标签只引用品牌色或品牌派生语义属性
13. Rust 代码高亮不再选择 `base16-ocean.dark`
14. Rust 代码高亮主题将关键字、字符串、常量、函数/类型名和注释映射到已确认的品牌色
15. 已支持语言继续生成语法高亮，不支持语言继续安全回退为纯文本
16. 代码块行号数量、逐行结构和语言标签行为保持不变
17. App Shell 仍能正确加载三套主题 CSS
18. HTML 和 PDF 导出相关现有测试继续通过
19. 三套主题的 `.mermaid-block__error` 都引用 `var(--danger)`，不保留固定错误色值

## 手动检查

使用 `examples/brand-colors.md` 进行验证。

### Default 主题

1. 运行 `scripts/build_app.sh`
2. 启动确认来自 `dist/MarkHola.app` 的进程
3. 打开 `examples/brand-colors.md`
4. 选择 `View > Theme > Default`

预期：

- 表头背景为 `#EAF9F5`
- 表头文字清晰
- 表格正文、边框、间距与当前样式一致
- 链接为 MarkHola Violet，鼠标经过后为 MarkHola Green
- Tab 鼠标经过显示 Violet Tint，活动 Tab 底部横线为 MarkHola Green
- Outline 展开状态与条目悬停分别显示绿色和紫色色阶
- 代码区和行号区呈现紫色派生的深色表面
- 行号、语言标签、关键字、字符串和常量来自对应品牌色阶

### Light 主题

1. 选择 `View > Theme > Light`

预期：

- 表头仍为相同的 `#EAF9F5`
- 主题切换不会改变表头品牌色值
- 表头文字清晰
- Tab、链接和 Outline 的品牌色映射与 Default 主题一致
- 代码展示颜色与 Default 主题使用同一品牌语法色板

### Dark 主题

1. 选择 `View > Theme > Dark`

预期：

- 表头仍为 `#EAF9F5`
- 表头使用适合淡色背景的深色文字
- 表格正文继续符合深色主题
- 品牌色悬停背景上的文字保持清晰
- Tab、链接和 Outline 不再回退到旧蓝色强调色
- 代码区与行号区层级清晰，语法文字在深色表面上可读

### 代表状态

1. 在只读模式检查表格真实渲染
2. 切换到可写模式，确认 Markdown 源文本仍可正常编辑
3. 切回只读模式，确认淡绿色表头恢复显示

## 视觉证据

对 `Default`、`Light`、`Dark` 三个主题分别验证三组状态：

- 文档状态：链接、引用块、表格表头
- 交互状态：Tab 悬停与活动横线、Outline 展开与条目悬停
- 代码状态：行号区、代码区、语言标签以及关键字、字符串、常量和注释

1. 使用可访问性树确认已打开 `brand-colors.md`
2. 截取包含链接、引用块、完整表头和完整代码块的真实 App 截图
3. 打开 Outline 并触发代表性的 Tab/Outline 悬停状态，再截取交互状态截图
4. 检查颜色、位置、尺寸、文字对比度以及活动状态层级

截图结果优先于 CSS 字符串检查；如果真实渲染与预期不一致，应先修复再完成交付。

## 回归检查

- 主题切换继续即时生效
- Markdown 普通段落样式不受影响；代码块布局与行为不受影响；链接目标与打开行为不受影响
- 表格单元格对齐与边框不受影响
- 代码块行号、滚动、语言标签和语法识别行为不受影响
- HTML 和 PDF 导出仍可完成
- 警告、错误、删除和查找命中仍使用各自语义色

## 发布前检查

实现完成后生成 `UDZO` DMG，并在发布前使用候选 DMG 做沙箱验证。验证记录应包含候选 DMG 路径、复制后的 App 路径、实际测试进程路径，以及证明运行目标构件的关键日志。
