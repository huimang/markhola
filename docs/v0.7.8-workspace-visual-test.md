# v0.7.8 工作区主视觉测试文档

## 目标

验证 `v0.7.8` 已确认的工作区主视觉调整：

1. 扁平、无文件图标的文档 Tab
2. 单一 Logo 衍生色的活动 Tab 下划线
3. 固定在最右侧的 `+` 新建文档快捷按钮
4. 仅在 Tab 溢出时显示前后导航
5. 只读模式右侧 Outline / TOC 面板
6. 只读模式不显示 reading rail
7. 可写模式继续使用现有行号
8. 未打开文档时在居中提示文字左侧显示不带 slogan 的 MarkHola App 图标
9. 多个空白文档使用依次递增的 `Untitled-N` 标题
10. 顶部 `document-toolbar` 被移除，文档信息进入只读原生底部状态栏

## 自动化检查

1. 应用外壳 HTML 不包含工作区 brand-mark
2. 渲染后的文档 Tab 不包含 Markdown 文件类型图标
3. 应用外壳包含固定右侧的 `+` 新建文档控件
4. `+` 控件发送现有新建文档事件
5. 应用外壳不包含已移除的通用 more-button
6. 应用外壳包含前后 Tab 导航控件
7. Tab 溢出逻辑可以隐藏和显示导航控件
8. 激活 Tab 时会请求将该 Tab 滚动到可见区域
9. 应用外壳包含右侧 Outline 面板和供原生 View 菜单调用的显隐函数
10. Outline 按文档顺序包含 `h1` 至 `h6`
11. Outline 保留可见的标题层级
12. 无标题文档产生 Outline 空状态
13. 三个主题样式都包含相容的 Tab 和 Outline 样式
14. 只读模式不增加行号或 reading-rail 组件
15. 可写模式继续使用现有编辑器行号组件
16. 应用外壳不包含 `document-toolbar`
17. 原生底栏依次包含路径、Words、Lines、模式值和状态值，且不包含按钮、字号或 Outline
18. 模式切换后原生模式文本只显示 `Readonly` 或 `Writable`
19. 原生状态区域只显示当前状态，不显示 `Status` 前缀
20. 原生底栏最左侧显示真实文件路径或 `Unsaved draft`
21. 没有打开文档时隐藏 Tab 区域，并将空状态卡片置于页面正中
22. 没有打开文档时原生底栏不显示 `Ready` 或其他状态文字
23. 打开文档后 Tab 区域高度为紧凑的 `36px`
24. 应用、HTML 导出和 PDF 导出的 Mermaid 渲染都会清理 `d<render-id>` 临时节点
25. 无文档空状态包含 `empty-state__icon`，使用内嵌 App 图标数据并提供 `MarkHola` 替代文本
26. 空白文档编号独立递增，普通已打开文件不消耗 `Untitled-N` 序号

## 手动检查

### 无文档空状态

1. 启动应用且不打开任何文档
   预期：MarkHola App 图标位于左侧，`No document opened` 与说明位于右侧，整体在剩余工作区水平及垂直居中

2. 检查图标
   预期：使用现有 `assets/app-icon.png`，不包含 MarkHola 字标或 slogan，不裁切、不拉伸

3. 分别在浅色和深色主题检查空状态
   预期：图标与背景保持清晰区分，提示文字布局不跳动

该状态以“无文档”作为验证入口，不新增示例 Markdown 文件。

### 空白文档标题

1. 连续新建三个空白文档
   预期：Tab 标题依次为 `Untitled-1`、`Untitled-2`、`Untitled-3`

2. 关闭 `Untitled-2` 后再次新建空白文档
   预期：新 Tab 标题为 `Untitled-4`，不会复用已关闭文档的序号

3. 先打开一个已有 Markdown 文件，再新建空白文档
   预期：已有文件不会额外消耗空白文档序号

### Tab 外观

1. 启动应用并打开一个 Markdown 文档
   预期：Tab 栏没有 brand-mark，Tab 没有文件类型图标

2. 检查活动 Tab
   预期：使用一条绿色 Logo 衍生色下划线，不使用双色渐变

3. 检查非活动、悬停、活动和键盘焦点状态
   预期：状态清晰可区分，同时避免视觉噪声

4. 修改活动文档
   预期：脏状态标记保持可见，关闭按钮正常工作

5. 在 Default、Dark 和 Light 主题之间切换
   预期：Tab 结构保持稳定，文字清晰可读

### 原生底部状态栏

1. 打开文档并滚动只读正文
   预期：Tab 下方不再显示 `document-toolbar`；底部状态栏固定在 WebView 外部

2. 切换到可写模式并滚动编辑器
   预期：底部状态栏保持固定

3. 检查底栏顺序
   预期：从左到右依次为文件路径、Words、Lines、Readonly/Writable、状态内容

4. 检查底栏交互
   预期：底栏全部为只读文本，不存在模式、字号或 Outline 按钮；模式和状态均不带字段名前缀

5. 缩窄窗口
   预期：最左侧路径优先省略，右侧只读信息保持可见

### 新建文档快捷按钮

1. 点击固定在最右侧的 `+`
   预期：创建空白 Markdown 文档并将其设为活动文档

2. 与 `File > New` 和 `Command + N` 对比
   预期：三个入口使用同一套文档创建行为

3. 保存新文档
   预期：Tab 标题更新为所选文件名

### Tab 溢出

1. 打开文档，直到所有 Tab 仍可完整显示
   预期：前后导航按钮隐藏，`+` 固定在最右侧

2. 继续打开文档，直到 Tab 栏溢出
   预期：`‹` 和 `›` 出现在固定 `+` 的左侧，Tab 不换行

3. 点击 `›`
   预期：较后的 Tab 进入可见区域

4. 点击 `‹`
   预期：较早的 Tab 返回可见区域

5. 通过现有 Tab 切换快捷键激活当前被裁切的 Tab
   预期：活动 Tab 自动滚动到可见区域

6. 关闭部分 Tab，直到剩余 Tab 可以完整显示
   预期：前后导航按钮消失

7. 调整窗口宽度并跨过溢出临界点
   预期：导航按钮显示状态自动更新，不重新加载工作区

8. 在以上所有状态检查 `+`
   预期：`+` 始终可见并固定为最右侧控件

### Outline / TOC

1. 在只读模式打开 `examples/workspace-visual.md` 并展开 View 菜单
   预期：Outline 菜单项可用且未勾选

2. 选择 `View > Outline`
   预期：面板在右侧打开，菜单项显示勾选，文档使用剩余宽度；再次选择后关闭并取消勾选

3. 检查 Outline 条目
   预期：标题按文档顺序显示，并具有清晰层级

4. 点击多个 Outline 条目
   预期：文档滚动到对应标题

5. 点击面板内部关闭按钮
   预期：面板关闭，文档重新使用完整宽度

6. 再次打开面板并切换到另一个只读文档
   预期：面板更新为活动文档的标题

7. 打开没有标题的文档
   预期：面板显示空状态

8. 打开包含 `[toc]` 的文档
   预期：正文内 TOC 和右侧 Outline 面板互不影响

9. 切换到可写模式
   预期：Outline 面板关闭，菜单项取消勾选并禁用

### 只读与可写 rail

1. 检查只读模式
   预期：不显示左侧 reading rail 或行号列

2. 切换到可写模式
   预期：显示现有编辑器行号

3. 在多行文档中输入和滚动
   预期：编辑器文字和行号保持对齐

4. 从 `View > Size` 调整字号
   预期：编辑器文字和行号一起缩放；只读模式仍不显示 rail

### 原生底栏和全屏

1. 打开并关闭 Outline 面板
   预期：原生底栏固定在 WebView 外部

2. 向前和向后滚动 Tab
   预期：原生底栏状态保持正确

3. 进入并退出全屏
   预期：Tab 栏、溢出导航、Outline 面板和底栏仍可正常使用

### Mermaid 失败渲染

1. 打开一个包含无效 Mermaid 图表的文档，使 Mermaid 进入错误分支
   预期：错误信息只出现在对应文档的 Mermaid 区块内

2. 随后切换到 `/Users/xiaolongdeng/Downloads/math.md`
   预期：页面根级不保留 `dmermaid-*` 错误 SVG，`error-text` 不会占据正文区域的完整宽度
